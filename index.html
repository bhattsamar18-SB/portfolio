01 — About

A designer who
writes the code.

Samar Bhatt Computer Engineering · UI/UX Developer

I sit exactly where design meets engineering. As a Computer Engineering diploma student I learnt how systems think; as a UI/UX Developer I learnt how people feel. My work is the handshake between the two — interfaces that are researched, prototyped and then built properly.

I start with the messy part: user flows, edge cases, and the question "what is this screen actually for?". Then come wireframes, a token-driven design system, and a high-fidelity prototype. Finally I hand it to myself and ship it in HTML, CSS and JavaScript — responsive, accessible and animated at 60fps.

Three.js r160 Scroll into view to load
  • Lazyimported on scroll

06 — Process

How a screen
earns its place.

Five steps, repeated until the interface feels obvious.

01

Discover

Interviews, competitor teardowns and job-to-be-done mapping. I define the problem before touching a canvas.

02

Structure

Information architecture, user flows and low-fidelity wireframes — fast, ugly and honest.

03

Design

Type scale, colour roles, spacing rhythm and components — assembled as a reusable token-based system.

04

Prototype

Clickable prototypes with real motion, then usability testing to catch friction before dev time is spent.

05

Build

Semantic HTML, scalable CSS, vanilla JS and GSAP — responsive, accessible, and fast on real devices.
